# Detection


| Quirk | Where observed | Handling |
|---|---|---|
| New document format: multi-sheet spreadsheet, not a paginated document | Both workbooks are `.xlsx` files with multiple named sheets, not PDFs with pages. | Per `skills/version-compare/Skill.md` Module 6 ("Mixed or converted formats"), normalized both workbooks to extracted per-sheet text before applying grain and verdicts — comparison operates on that normalized text, not on spreadsheet-specific rendering. Twin files use `sheet-<name>.md` instead of `page-###.md`, adapting `Bootstrap.md` §12's per-unit twin convention to this document type's actual unit of location (a sheet, not a page). |
| A whole new sheet added, with no counterpart at all | The source workbook has a sixth sheet, "Cybersecurity Addendum," entirely absent from the supporting workbook (confirmed by listing every sheet name in both workbooks, not just checking one). | Judged as a sheet-level ADDED unit: every row within the new sheet is ADDED (no counterpart exists), consistent with skill Module 1's ADDED rule — this is a larger-scope application of the same rule already used for S2's whole-section removal, not a new rule. |
| A whole new table column added within an existing sheet | The Requirements Matrix sheet's "Vendor Response (F/P/C/N)" and "Vendor Notes" columns exist only in the source workbook — the supporting workbook's Requirements Matrix has no data or headers in columns E/F at all. | Judged as one column-level ADDED note per sheet (not duplicated across all 17 rows) since the absence is structural (an entire column, not per-row content), while each row's own requirement text/priority is still judged independently per skill Module 1's one-clause grain. |
| Row ID skipped, not renumbered | The source workbook's Requirements Matrix jumps from R-06 directly to R-08 — R-07 does not appear at all, with an explicit note: "R-07 (on-premise-only network monitoring) has been removed from this revision and replaced by R-17 (cloud-managed monitoring)." | Mapped R-07 as REMOVED (quoting its old text from the supporting workbook) and R-17 as ADDED (a distinct new requirement, not a renumbering of R-07, despite the note's "replaced by" language) — per skill Module 2 stage MAP, mapping by content, not ID: R-17's actual requirement text ("cloud-managed network monitoring platform with mobile alerting") is substantively different from R-07's ("on-premise network monitoring dashboard"), so this is REMOVED + ADDED, not a single CHANGED clause, even though the document's own note frames it as a replacement. |
| Placeholder zero values vs. real prices | The supporting workbook's Pricing Form has every Unit Price and Extended Price cell set to `0` (a placeholder, since it is the original unfilled RFP template); the source workbook's Pricing Form has real, non-zero unit prices, quantities, and extended totals filled in. | Judged as CHANGED (the placeholder `0` is the old value, the real figure is the new value) for every price cell with a row counterpart, since a counterpart row plainly exists — not as ADDED, since ADDED would imply no prior version of that line item existed at all. |
| Third occurrence of self-annotation | The source workbook marks changes with the same bracketed-tag convention (`[NEW]`, `[MODIFIED]`, `[UPDATED]`) as both prior samples (S1, S2), now inside spreadsheet cell text rather than PDF prose. | Already promoted into skill v2 Module 6 from S1 (plus explicit user generalization) and reconfirmed by S2 (cross-sample). This is a third independent confirmation, across a third document format — logged in `skills/version-compare/PatternLog.md`, no further skill change needed. |
| Cover sheet's "Category" field is unchanged even though the document title changed | The source workbook's title (A7) changes from "District-Wide Network & Wi-Fi Infrastructure Refresh Program" to "District-Wide Network, Wi-Fi Infrastructure & Cybersecurity Enhancement Program," but the Category field (B13) — "K-12 IT Infrastructure — Network, Wi-Fi & Cybersecurity" — is byte-identical in both workbooks, since the original's Category field already mentioned cybersecurity even though its title and scope did not yet include it. | Judged UNCHANGED for the Category clause specifically, independent of the title clause's CHANGED verdict — confirms the grain rule (each clause judged on its own wording) rather than assuming every cover-sheet field moved together because the sheet as a whole clearly changed. |
