# Detection

Recorded here per-document; anything that recurs across
independent samples is a candidate for `skills/version-compare/PatternLog.md` (see

| Quirk | Where observed | Handling |
|---|---|---|
| Self-annotation | The source document marks most of its own additions/changes with bracketed tags (`[NEW]`, `[MODIFIED]`, `[REFORMATTED — ...]`, `[REMOVES ...]`) throughout nearly every section. | Used only as a cross-check, per `skills/version-compare/Skill.md` Module 6 — every marked and unmarked clause was independently compared against the supporting document's text regardless of any marker. Same pattern already logged and promoted into skill v2 Module 6 from the S1 sample plus explicit user generalization (`skills/version-compare/PatternLog.md` Entry 1/3); this is a second, independent occurrence, confirming the already-promoted rule (`skills/version-compare/PatternLog.md` Entry 4). |
| Whole section reserved/emptied | Section 6, "Vendor Onboarding & Staffing Requirements" in the original, is retitled "[Reserved]" in the revised issue: its five substantive bullets are removed entirely and replaced with a short note that the content now lives in the MSA. The section *number* and table-of-contents slot persist; only the content changed. | Judged as REMOVED for each of the five original bullets (each independently, per the skill's one-clause grain), plus one ADDED unit for the new "[Reserved]" explanatory note itself, since that note is new text with no counterpart in the original. This is a variant of "whole section removed" not seen in the S1 sample — S1 never removed an entire section, only individual clauses. |
| Reformatted prose → table | Section 5.5, "Vendor Support Responsibilities," is bullet-point prose in the original and a table in the revised issue, explicitly marked `[REFORMATTED — PRESENTED AS A TABLE IN THIS REVISION]`, with the revision's own note stating "Rows 1–5 restate the equivalent bullet-point content ... updated to a tabular format with explicit SLA targets added." | Each original bullet was matched to its corresponding table row by content, not position (per skill Module 2 stage MAP). Where the row's substance matches the bullet but adds an explicit SLA target/number, judged CHANGED (the underlying obligation is the same fact, restated with an added quantified term) rather than one REMOVED + one ADDED — since the skill's absence-policy requires REMOVED/ADDED only when there is no counterpart at all, and here there plainly is one, just reformatted. The new "Major Incident Response" row has no bullet counterpart in the original at all, so it is ADDED. |
| Table row wrapped across a page break | The Vendor Support Responsibilities table's header row repeats on the second PDF page it spans (page 6), immediately followed by the continuing rows. | Treated as one continuous table for judgment purposes — the repeated header is a PDF rendering artifact of the page break, not a second table, and was not itself judged as a unit. |
| New standalone subsection with no original counterpart | Section 13.3, "Service Level Credit Schedule," is explicitly marked `[NEW — NO EQUIVALENT CONTENT IN ORIGINAL RFP]` and is not present anywhere in the original document (checked by search, not just by absence from a single page). | Judged ADDED as a whole new subsection (three SLA-credit rows), consistent with skill Module 1's ADDED rule requiring a search-confirmed absence in the older document. |
| Explicit "unchanged" notes | The revised document itself states, in prose, that several sections/appendices are unchanged from the original (Definitions, Insurance Requirements, Terms & Conditions 15.1–15.4, Appendix B). | These self-declared "unchanged" notes were treated as a claim to verify, not as evidence on their own — each such section was still independently compared clause-by-clause against the original per skill Module 1's "no verdict from one side" rule, and confirmed UNCHANGED by that independent comparison, not by trusting the note. |
